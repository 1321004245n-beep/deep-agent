# 调试技能

## 何时使用
- 用户报告错误、异常、程序不工作、行为不符合预期

## 排查流程
1. **复现**：拿到完整错误信息（报错文本、堆栈、日志）和复现步骤；复现不了就问清楚触发条件
2. **定位**：用二分法缩小范围——最新改动 vs 一直存在、特定输入 vs 所有输入、生产 vs 本地；先看错误堆栈顶部，再读相关代码和日志
3. **找根因**：分析"为什么"而不是"怎么改"，问自己：这个 bug 的本质原因是什么？不要靠猜测堆修复
4. **最小修复**：做最小改动解决问题，不顺手重构无关代码；改动会引入风险时先说明
5. **验证**：修复后重新运行复现步骤确认解决，再检查是否引入新问题

## 常见陷阱
- 别盲目试错：连续两次同样的尝试失败就停下来重新分析
- 别忽视"最近改了啥"：大部分 bug 来自最近的变更（`git diff` / `git log`）
- 输出型调试优先：加日志/打印确认假设，比盯着代码猜更快
- 环境差异：本地正常但线上挂，优先怀疑环境变量、依赖版本、系统差异
