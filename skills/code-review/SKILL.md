# 代码审查技能

## 何时使用
- 用户要求审查代码、找 bug、评估代码质量、检查 PR

## 审查步骤
1. **理解意图**：先读相关文件和上下文，搞清楚这段代码要做什么，不要只看孤立片段
2. **逐层检查**，按以下维度过一遍：
   - 正确性：逻辑是否成立，边界情况（空值、超限、并发）
   - 性能：是否有明显的低效路径（循环内 IO、重复计算）
   - 可维护性：命名、函数长度、重复代码、可读性
   - 安全：注入、敏感信息硬编码、权限检查缺失
3. **分级输出**：
   - 🔴 严重（必须修）：会导致错误结果、崩溃或安全问题
   - 🟡 建议（应该修）：影响可维护性或潜在隐患
   - ⚪ 风格（可选）：命名、格式等主观偏好
4. 每条问题**附上具体位置（文件+行号或代码片段）和修改建议**，能给出修复示例代码最好
5. 最后给一句总体评价（可用性、代码质量评分倾向）

## 注意事项
- 不要吹毛求疵：风格问题归为"风格"级，别刷屏
- 不确定的问题标注"需确认"，不要断言
- 先给结论摘要，再展开细节
