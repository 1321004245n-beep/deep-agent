# Git 工作流技能

## 何时使用
- 用户要求提交代码、创建分支、查看变更、回滚等 git 操作

## 提交流程
1. **先看状态**：`git status` + `git diff` 确认改动内容，绝不盲目提交
2. **检查敏感信息**：确认没有 .env、密钥、token、日志文件混入（必要时用 `git diff --stat` 快速过一遍）
3. **小步提交**：一个逻辑变更一次提交，不要一个 commit 塞一堆无关改动
4. **提交信息格式**（Conventional Commits）：
   - `feat: 新功能` / `fix: 修复` / `refactor: 重构` / `docs: 文档` / `test: 测试` / `chore: 杂项`
   - 格式：`type(scope): 简述`，如 `fix(auth): 修复登录态过期后仍可访问的问题`
   - 信息写"做了什么"，不写"怎么做的"
5. **提交后验证**：必要时跑测试或构建确认没搞坏

## 常见操作提醒
- 切换分支前确认工作区干净（`git status`）
- 删除/回滚是破坏性操作，先确认再执行
- 拉取远程代码用 `git pull --rebase` 保持历史线性（团队约定时）
